# 기획: 편향 가정 모드 & 비인기 조합 모드

## 0. 배경

지금까지 이 프로젝트 데이터(1~1236회차)로 확인한 사실:

- 번호별 출현비율 편차(11.0%~15.0%)는 이항분포 기대 표준편차 범위 안 (통계적으로 무작위와 일치)
- 미출현 간격(gap)별 재출현율도 12.5~13.6%로 평평함 (도박사의 오류 반증)
- 쌍(pair) 동시출현 분산도 무작위 가정 이론값과 거의 동일, 카이제곱 939/자유도989로 유의미한 상관 없음

즉 **"과거 데이터로 다음 당첨 확률을 높이는 신호는 없다"**는 게 이 프로젝트 자체 분석 결과입니다. 이 전제 위에서 아래 두 기능을 설계합니다. 둘 다 "당첨 확률을 실제로 높인다"는 주장은 하지 않고, 각각 다른 목적을 가진 실험적 생성 규칙으로 정직하게 포지셔닝합니다.

- **모드 A (편향 가정)**: "혹시 조작/편향이 있다면" 이라는 가정 하에, 그 편향을 잡아낼 가능성이 조금이라도 있는 통계 신호(최근 회차 가중치)를 쓰는 실험적 모드. 재미/실험 목적이며 근거가 약하다는 문구를 UI에 명시.
- **모드 B (비인기 조합)**: 당첨 확률 자체는 다른 조합과 완전히 동일하지만, 당첨됐을 때 **1등 당첨금을 나눠 가질 사람 수를 줄여 기대 상금을 높이는** 것이 목적. 이건 통계적으로 실제 근거가 있는 전략입니다 (로또 상금은 1등 당첨자 수로 나눠 지급되므로, 남들이 잘 안 고르는 조합을 고르면 당첨 시 받는 몫이 커짐).

## 1. 모드 A: 편향 가정 모드 ("biased")

### 1-1. 컨셉

현재 `generate.py`의 고확률/저확률 풀은 **전체 1236회차 누적 비율**을 씁니다. "조작이 있다면"이라는 가정을 좀 더 그럴듯하게 반영하려면, 조작은 특정 시점부터 시작됐을 가능성이 높으므로 **최근 N회차에 가중치를 더 주는 방식**이 전체 누적 방식보다 이론적으로 더 타당합니다 (물론 여전히 "가정"일 뿐, 이번 세션에서 확인했듯 실제 신호는 못 찾았습니다).

### 1-2. 알고리즘 제안

- `number_stats`와 별개로 `number_stats_recent` 개념 도입 (또는 기존 테이블에 window 파라미터 추가)
- 최근 회차일수록 가중치를 높이는 지수가중이동평균(EWMA) 방식: `weight = decay^(latest_round - draw_round)`
- 사용자가 조절 가능한 파라미터: 최근 N회차 (예: 최근 50 / 100 / 200회) 또는 decay 계수
- 전체 누적 비율(현재 방식)과 최근 가중 비율을 **같이 보여줘서** 얼마나 차이가 나는지 비교 (차이가 거의 없다면 "역시 편향 없음"을 사용자가 직접 확인 가능 → 정직한 도구)
- 상위/하위 풀 선정 로직은 기존 `generate_combination`과 동일하게 재사용, 풀 소스만 `number_stats`→`number_stats_recent`로 교체

### 1-3. UI/문구

- 버튼: "편향 가정 (최근 N회 가중)"
- 설명 문구: "최근 회차에 더 높은 가중치를 줘서 혹시 있을지 모를 편향을 잡아보는 실험 모드입니다. 지금까지 데이터로는 유의미한 편향이 발견되지 않았습니다."
- 결과 카드에 "전체 누적 순위 대비 몇 계단 변동" 같은 부가 정보 표시하면 재미 요소 + 투명성 둘 다 챙길 수 있음

## 2. 모드 B: 비인기 조합 모드 ("unpopular")

### 2-1. 배경 지식 (사람들이 실제로 어떻게 번호를 고르는가)

동행복권은 번호별 실제 선택 비율(수동/자동 구매 데이터)을 공개하지 않아서, 국내 로또에 특화된 정확한 "인기 번호" 데이터는 구할 수 없습니다. 대신 해외 로또(파워볼 등) 연구와 행동경제학에서 반복적으로 확인된, 로또 종류와 무관하게 나타나는 일반적인 사람의 선택 편향 패턴이 있습니다:

- **생일 편향**: 사람들은 1~31 사이 숫자(생일 날짜/월)를 32~45보다 훨씬 더 많이 고름 → 32~45 위주 조합은 상대적으로 덜 선택됨
- **연속/등차수열 회피**: 사람은 "무작위처럼 안 보인다"는 이유로 (1,2,3,4,5,6) 같은 연속 조합이나 등차수열을 의식적으로 피함 → 실제 추첨에서는 다른 조합과 확률이 완전히 같은데도 사람들은 덜 고름
- **"행운의 숫자" 쏠림**: 3, 7, 8 같은 숫자가 다른 숫자보다 더 자주 선택되는 경향 (문화적 선호)
- **패턴 회피**: 배수(5, 10, 15...)로만 구성되거나, 마지막 자리 숫자가 전부 같은 조합(예: 4,14,24,34,...)도 "패턴처럼 보인다"는 이유로 회피됨
- **직전 당첨번호 회피**: 바로 전 회차 당첨번호와 겹치는 조합은 "설마 또 나오겠어"라는 생각에 회피되는 경향

이 항목들은 확률적으로는 전혀 의미가 없지만(모든 조합의 당첨 확률은 정확히 동일), **사람들이 덜 고르는 조합일수록 당첨 시 그 조합을 고른 다른 사람이 적다** → 1등 당첨금 분할 인원이 줄어 기대 상금이 커집니다.

### 2-2. 점수화 규칙 설계

각 후보 조합에 대해 "인기 점수(popularity score)"를 계산하고, 낮은 점수의 조합을 우선 채택하는 방식을 제안합니다.

| 규칙 | 감점 조건 | 근거 |
|---|---|---|
| 생일 범위 쏠림 | 6개 중 32~45 범위 번호가 2개 미만 | 32~45 비중이 낮을수록 인기 조합 |
| 연속 번호 | 연속된 숫자 쌍이 있음 (예: 13,14) | 사람들이 회피 → 오히려 저인기 |
| 등차수열 | 3개 이상 등차수열 성립 | 매우 회피됨 → 저인기 |
| 배수/패턴 | 전부 5의 배수, 또는 마지막 자리수 동일 | 회피 패턴 |
| 합계(sum) 극단값 | 6개 합이 100~170(평균 근처) 범위 안 | 사람은 평균 근처 "그럴듯한" 합을 선호 → 극단적으로 낮거나(<100) 높은(>170) 합은 저인기 |
| 직전 회차 중복 | 직전 회차 당첨번호와 1개 이상 겹침 | "설마 연속으로 또" 심리로 회피됨 |

주의: 위 규칙들은 서로 방향이 반대일 수 있어(연속 번호 회피 vs 생일범위 회피) 실제로는 **가점을 주는 방식**(사람들이 회피하는 특징을 조합에 "의도적으로 포함"시키는 방식)으로 설계하는 게 자연스럽습니다. 즉 기존 고확률/저확률 풀에서 숫자를 뽑는 대신, 32~45 비중을 높이고, 연속 번호나 등차수열을 일부러 섞고, 극단적인 합계를 갖도록 유도합니다.

### 2-3. 정직성 문구 (중요)

이 모드는 반드시 아래 문구를 UI에 명시해야 합니다:
> "이 조합은 당첨 확률을 높이지 않습니다. 모든 조합의 당첨 확률은 동일합니다. 다만 다른 사람이 이 조합을 고를 가능성이 낮아서, 당첨 시 상금을 나눠 가질 인원이 줄어들 수 있다는 것이 이 모드의 목적입니다."

## 3. 구현 계획 (기존 코드베이스 반영)

- **`lotto/generate.py`**: `SlotRule`에 `"biased"`, `"unpopular"` 추가. `unpopular`용 `_popularity_score(numbers)` 함수와, 조건을 만족할 때까지 후보를 재생성하는 필터 로직 추가.
- **`lotto/stats.py`**: 모드 A용 `compute_recent_number_stats(window=100)` 함수 추가 (기존 `compute_number_stats`와 별도).
- **`lotto/db.py`**: 모드 A용 `number_stats_recent` 테이블 스키마 추가 (또는 `number_stats`에 `window` 컬럼을 추가해 여러 윈도우를 저장).
- **`lotto/web.py`**: `VALID_RULES`에 두 규칙 추가.
- **`lotto/templates.py`**: 버튼 2개 추가 + 위 정직성 문구를 각각 footer/설명에 반영.
- **`scripts/`**: 필요시 `check_db.py`에 recent-stats 정합성 체크 추가.
